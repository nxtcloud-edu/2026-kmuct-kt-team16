## 1. 목표 (MVP의 정의)

실제 스크린샷 이미지를 넣으면 아래 전 과정이 실제로 동작해야 한다.

1. **분류**: AI가 이미지를 읽고 행동(ACTION) / 기억(MEMORY) / 불확실(UNCERTAIN)로 나누고 제목·날짜·장소·카테고리를 뽑는다.
2. **저장**: 확실한 것은 사용자 확인 없이 즉시 저장한다(일정 또는 보관함). 불확실한 것은 "확인 필요"에 쌓는다. 모든 자동 처리는 되돌릴 수 있다.
3. **위치 저장**: 장소가 있는 기억 항목과 브랜드 쿠폰은 자동으로 좌표를 얻어 지오펜스 감시 대상이 된다.
4. **알림**: 장소 근처에 머물면 위치 알림, 일정·마감·쿠폰 만료가 다가오면 시간 알림을 보낸다.

## 2. 기준 UI: `Snaptok/index.html`

내가 `Snaptok/index.html`에 넣어 둔 단일 파일 웹 데모가 기준 UI다(같은 폴더의 `README.txt`는 데모 설명)(순수 HTML/CSS/JS, 크림·코랄 디자인). 화면과 디자인은 그대로 유지하고, 데이터 흐름을 실제로 연결하는 것이 이번 작업이다.

### 2.1 이미 잘 구현되어 있어 재사용할 것

- 탭 구성(오늘, 보관함, +, 활동, 결산), 캘린더 화면, 시트, 토스트, `#push`, `#geoBanner` 배너 UI.
- 다중 업로드(최대 8장), 클라이언트 이미지 압축 `fileToCompressed`, 진행 표시 `runAnalysis`.
- 중복 감지 `similarity`(바이그램)와 `findDuplicateEvent/Library`.
- 되돌리기 `undoRecent`, 활동 기록 `logRecent`, 확인 필요 큐 `renderReviewQueue/resolvePending`.
- **지오펜스 엔진**(`geoTick`, `attemptNotify`, `geoMessage`, `fireGeoNotification`, `openGeoSettings`, 위치 시뮬레이터 `GEO_PRESETS/geoMoveTo`): 체류(데모 10초/실제 180초), 이탈 여유 30m, 7일 쿨다운, 하루 2개 상한, 시간대, 브랜드 매장 최소 거리, 사용한 쿠폰, 다시 알리지 않기, 알림 기록. 규칙 로직은 유지한다.
- 결산 화면(실제 데이터 기반 집계).

### 2.2 반드시 고칠 문제 (코드 검토 결과, 실제 실행으로 확인됨)

1. **AI로 분석한 새 항목이 지오펜스 대상이 되지 않는다.** `addLibraryAuto`가 만드는 항목에 `geoType`, `lat`, `lng`, `branches`, `expiry`가 없고, `geoTargets()`는 `geoType`이 있는 항목만 감시한다. 지오펜스 대상은 시드 데이터 4개뿐이다.
2. **이미지 속 쿠폰이 위치 알림으로 이어지지 않는다.** 사용기한이 있는 쿠폰은 ACTION으로 분류되어 일정(`events`)으로만 저장되고, 보관함 쿠폰·브랜드 지오펜스가 만들어지지 않는다.
3. **위치 시스템이 두 개로 나뉘어 있다.** 예전 `triggers` 시스템("지금 이 주변" 카드, "여기서 다시 알려주기", 실제 GPS 감시 `ensureWatcher`)과 지오펜스 엔진이 따로 돈다. "여기서 다시 알려주기"는 항목의 장소가 아니라 **버튼을 누른 순간 사용자의 현재 위치**를 저장해서, 집에서 저장한 맛집은 집 근처에서 울린다. `fireTrigger`는 쿨다운·상한 규칙을 거치지 않고, 카드의 "N개 등록" 숫자도 실제 감시 대상과 다르며, 실제 위치 모드에서는 알림이 두 번 뜰 수 있다.
4. **"자동 등록"이 실제로는 자동이 아니다.** 분석 결과 시트에 "✅ 캘린더 자동 등록" 배지가 뜨지만 [저장하기]를 누르기 전까지 아무것도 저장되지 않고, 시트를 닫으면 분석 결과가 모두 사라진다.
5. **시간 알림이 없다.** 일정은 앱 내부 캘린더에만 저장되고, 마감·쿠폰 만료가 다가와도 사용자에게 알리는 장치가 없다.
6. **AI 분석이 Claude 아티팩트 런타임(`claude.use('sample')`)에서만 동작한다.** 그 밖의 환경에서는 파일명 키워드로 분류하는 대체 로직만 돈다. MVP는 서버의 LLM API로 분석해야 한다.
7. **날짜 처리가 약하다.** 항목당 날짜가 하나뿐이라 한 포스터의 "신청 마감"과 "행사 당일"을 나누지 못하고, 근거 확인이나 지난 날짜 처리가 없다. `TODAY='2026-09-20'`와 캘린더 월(2026년 9월)이 하드코딩되어 있다.
8. **이미지를 base64로 localStorage에 저장한다.** 실제 스크린샷 수십 장이면 저장 한도를 넘고, `saveAll`은 실패를 콘솔에만 남겨 사용자는 저장된 줄 알다가 새로고침 후 데이터를 잃는다.
9. **개인정보 문구와 실제가 다르다.** "위치 좌표 자체는 저장하지 않는다"고 하지만 `triggers`는 사용자 GPS 좌표를, 지오펜스 엔진은 `_status/_dist/_dwellStart` 실행 상태를 보관함 데이터와 함께 localStorage에 저장한다.

## 3. 아키텍처

```
snaptok_v2/
  SNAPTOK_MVP_PROMPT.md  이 문서
  Snaptok/  기준 UI(웹). 서버가 /app 경로로 제공
  server/   FastAPI: 분석(LLM), 저장(SQLite + 이미지 파일), 장소 좌표화, 구글 캘린더 동기화
  samples/  시연 이미지와 기대 결과
  docs/     PROGRESS.md
```

- 웹은 같은 출처의 `/api/*`를 호출한다. API 키(LLM, 카카오 REST, 구글)는 서버에만 둔다.
- 데이터의 원본은 서버 DB다. 웹의 localStorage는 화면 설정과 지오펜스 기록(쿨다운, 일일 카운트, 다시 알리지 않기, 모드)에만 쓴다.
- 지오펜스 판단은 브라우저 안에서만 한다. 사용자의 현재 위치는 Snaptok 서버로 보내지 않는다.

**첫 작업(리팩터링):** `Snaptok/index.html`은 base64 이미지 때문에 약 265KB라 수정할 때마다 비용이 크다. 동작을 바꾸지 말고 (1) 로고·해커톤 포스터 base64를 `Snaptok/assets/`의 이미지 파일로 빼고 (2) `<style>`을 `Snaptok/styles.css`, `<script>`를 `Snaptok/app.js`로 분리하라. 원본은 `Snaptok/index.original.html`로 남겨 둔다. 분리 전후 화면과 동작이 같아야 한다(주요 화면 스크린샷 비교).

## 4. 서버 명세 (server/)

**스택:** Python 3.11, FastAPI, SQLite(SQLAlchemy), 이미지는 `server/data/images/`. LLM은 공급자·모델을 환경변수로 바꿀 수 있게 추상화(멀티모달, JSON 출력).

**환경변수(.env.example):** `LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY`, `KAKAO_REST_API_KEY`(선택), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`, `GOOGLE_CALENDAR_ID`(모두 선택), `CALENDAR_SYNC`(off|google, 기본 off), `CONFIDENCE_ACTION`(0.7), `CONFIDENCE_MEMORY`(0.55), `DEFAULT_TIMEZONE`(Asia/Seoul), `DEMO_TODAY`(선택, 예: 2026-09-20).

### 4.1 엔드포인트

| 메서드 | 경로 | 용도 |
| --- | --- | --- |
| GET | /app/... | `Snaptok/` 폴더 정적 제공 |
| GET | /api/state | 초기 로드: events, library, review, recent, geoTargets |
| POST | /api/analyze | multipart: `image`, `captured_at`, `request_id`. 분석 후 **즉시 저장**하고 결과 반환 |
| PATCH | /api/library/{id} | 분류·제목·메모 수정, `geo_enabled` 켜고 끄기, `used: true`(쿠폰 사용) |
| POST | /api/library/{id}/location | `{"lat","lng"}`: 사용자가 "현재 위치를 이 항목 위치로" 명시적으로 지정할 때만 |
| DELETE | /api/library/{id}, /api/events/{id} | 삭제(구글 동기화된 일정도 함께 삭제) |
| POST | /api/review/{id}/resolve | `{"decision": "schedule"\|"memory"\|"delete", "category"?}` |
| POST | /api/recent/{id}/undo | 되돌리기: 해당 처리로 생긴 일정·보관·지오펜스를 모두 취소 |
| GET | /api/images/{id} | 원본 이미지 |
| POST | /api/wrapped-summary | 결산 AI 요약(P2) |

`request_id`가 이미 처리된 값이면 이전 결과를 그대로 돌려준다.

### 4.2 LLM 1회 호출

입력: 이미지, 캡처 시각, 오늘 날짜(`DEMO_TODAY` 또는 실제 날짜, 시간대 반영). 출력은 JSON만. 파싱 실패 시 1회 재시도 후 UNCERTAIN.

```json
{"type": "ACTION|MEMORY|UNCERTAIN", "confidence": 0.0,
 "title": "한 줄 제목", "category": "카테고리 하나 또는 null",
 "visible_text": "이미지 속 글자를 줄 단위로 그대로",
 "items": [{"kind": "task|event", "action_type": "apply|submit|use|book|attend|pay",
            "title": "", "date_role": "deadline|event|expiry|ticket_open",
            "date": "YYYY-MM-DD", "time": "HH:MM|null", "end_time": "HH:MM|null",
            "location": "", "evidence": "근거 문구"}],
 "place": {"name": "가게·장소 이름 또는 null", "area": "동네·지역 또는 null"},
 "brand": "체인 브랜드명 또는 null", "note": "짧은 메모"}
```

카테고리는 데모의 11개를 그대로 쓴다: 맛집, 여행지, 패션, 쿠폰, 전시회, 공모전, 생일, 영화, 콘서트, 공부, 기타.

프롬프트 기준(데모의 기준 문장을 살리되 보강): 행동 여부는 "기한까지 하지 않으면 손실이 생기는가". 한 이미지에 신청 마감과 행사일이 모두 있으면 items를 두 개로. 연도 없는 날짜·"내일"·"이번 주 금요일"은 오늘 날짜 기준. **이미지에 없는 날짜를 만들지 말 것.** 날짜 역할이 불분명하면 UNCERTAIN. 특정 이미지에 맞춘 규칙을 넣지 마라.

### 4.3 라우팅과 저장 규칙 (코드)

1. 유효 항목 = 날짜가 파싱되고, `evidence` 속 날짜 숫자가 `visible_text`에 존재하는 항목.
2. **ACTION**이고 `confidence >= CONFIDENCE_ACTION`이고 유효 항목이 있으면 자동 저장:
   - 각 유효 항목을 일정으로 저장(중복이면 건너뜀). 제목은 `"{title} · {행동}"` 형식 유지.
   - 기준 시각이 이미 지났으면(task=마감, event=종료, expiry=만료일 23:59) 일정 대신 보관함에 `missed` 표시로 저장.
   - `action_type == use`(쿠폰·기프티콘)이면 일정(만료 알림용)과 함께 **보관함 쿠폰 항목**도 만든다(category 쿠폰, `expiry`, `brand`).
3. **MEMORY**이고 `confidence >= CONFIDENCE_MEMORY`면 보관함에 자동 저장.
4. 그 외는 확인 필요(review)에 저장. 추출 결과는 모두 보관해서 사용자가 선택하면 LLM을 다시 부르지 않고 바로 처리한다.
5. 중복 판정은 데모의 바이그램 유사도(0.55)를 서버로 옮겨 쓴다.

### 4.4 장소 좌표화 (위치 저장)

보관함 항목이 저장될 때 서버가 좌표를 붙인다.
- **brand**(쿠폰에 brand가 있음, 또는 알려진 체인명): 좌표 없이 `geoType: brand`, `brand` 저장. 매장 좌표는 웹이 현재 위치 기준으로 찾는다(5.4).
- **specific**: `place.name`(+`area`)으로 카카오 키워드 검색 → 결과를 한 곳으로 좁히면 `lat/lng`, 반경 150m.
- **area**: 가게 이름 없이 동네·지역만 있으면(예: 연남동, 성수) 카카오 검색으로 동네 중심 좌표, 반경 700m.
- 카카오 키가 없거나 실패하면 `server/data/places_seed.json`(시연용 근사 좌표)에서 이름·지역으로 찾는다. 그래도 없으면 좌표 없이 저장하고 `geo_enabled=false`.
- 좌표가 붙은 항목 중 카테고리가 맛집, 여행지, 전시회, 패션, 콘서트, 쿠폰이면 기본으로 `geo_enabled=true`. 해외 장소(국내 검색 결과 없음)는 좌표 없이 둔다.

`places_seed.json`(좌표는 근사값이며 실제와 다를 수 있음을 주석에 명시): 연남동 파스타집 37.5663,126.9254 / 성수 생면 파스타 37.5446,127.0559 / 역삼 생면 파스타 37.5015,127.0380 / 연남동 중심 37.5660,126.9250 / 성수 중심 37.5446,127.0559 / 역삼 중심 37.5006,127.0364 / 스타벅스 매장 역삼역점 37.5007,127.0359, 강남역점 37.4979,127.0276, 선릉역점 37.5045,127.0490.

### 4.5 구글 캘린더 동기화 (P1)

`CALENDAR_SYNC=google`이면 자동 저장된 일정을 구글 캘린더에도 만든다. 알람: 신청·제출 마감 3일 전·1일 전, 쿠폰 만료 3일 전, 예매 오픈 10분 전, 행사 전날 20:00. 설명란에 근거 문구와 Snaptok 항목 ID. 되돌리기·삭제 시 함께 삭제. 실패해도 앱 내부 저장은 유지하고 결과에 `sync: failed`를 표시한다(거짓 "동기화됨" 금지). `off`면 호출하지 않는다.

## 5. 웹 변경 (Snaptok/)

### 5.1 데이터 계층 교체
- `load()/saveAll()`로 localStorage에 events·library·recent·review·triggers를 저장하던 부분을 서버 API로 교체한다. 시작 시 `GET /api/state`, 변경 시 해당 API 호출 후 상태 갱신.
- 저장 실패 시 콘솔이 아니라 토스트로 알리고, 화면 상태를 되돌린다.
- 이미지는 `/api/images/{id}` URL로 표시한다. base64를 localStorage에 넣지 않는다.
- 데모 시드 데이터는 서버 시드 스크립트로 옮기고(`seed: true`), 설정에 "시연 데이터 초기화"를 둔다.

### 5.2 분석 흐름 (자동 저장으로 변경)
- `analyzeOne`은 압축 이미지를 `POST /api/analyze`로 보낸다. `claude.use('sample')` 의존과 파일명 키워드 대체 분류는 제거한다(서버 오류 시에는 "분석 실패" 항목으로 확인 필요에 넣는다).
- 이미지마다 분석이 끝나는 즉시 서버가 저장한다. 결과 시트는 "처리 결과" 화면이 된다: 배지는 실제 상태(캘린더 저장됨 / 보관함 저장됨 / 확인 필요 / 중복 건너뜀 / 지난 마감)를 표시하고, 항목마다 [되돌리기]와 분류 변경을 둔다. [저장하기]는 [확인]으로 바꾸고, 시트를 닫아도 저장 결과는 유지된다.
- 저장이 끝나면 상단 배너(`#push`)로 요약을 띄운다. 예: "캘린더 2건 · 보관함 1건 · 확인 필요 1건", 위치가 등록되면 "연남동 파스타집 · 맛집 · 근처에 가면 알려드릴게요".

### 5.3 위치 시스템 통합
- 예전 `triggers` 시스템과 `ensureWatcher`/`fireTrigger`를 제거하고 지오펜스 엔진 하나로 통합한다.
- "지금 이 주변" 카드와 "N개 등록" 숫자는 지오펜스 감시 대상(`geo_enabled` 항목)을 보여준다. 카드의 거리 표시는 시뮬레이터 모드면 가상 위치, 실제 모드면 GPS 기준.
- 보관함 상세의 "📍 여기서 다시 알려주기"는 항목의 저장된 좌표로 `geo_enabled`를 켜고 끈다. 좌표가 없는 항목에만 "현재 위치를 이 항목 위치로 저장"을 별도 버튼으로 두고, 누르면 확인 문구를 보여준 뒤 `POST /api/library/{id}/location`.
- 실제 위치 모드에서 GPS 감시자는 하나만 두고 `geoTick`에 위치를 공급한다.
- 지오펜스 실행 상태(`_status`, `_dist`, `_dwellStart`)는 메모리에만 두고 저장하지 않는다.
- 쿠폰 [사용했어요]는 `PATCH used: true`로 서버에도 반영한다.

### 5.4 브랜드 쿠폰 매장 찾기
- `geoType: brand` 항목은 현재 위치(시뮬레이터면 가상 위치) 기준 가까운 매장 최대 3곳을 찾는다. 카카오맵 JavaScript SDK의 장소 검색(services 라이브러리, JS 앱 키, 도메인 등록 필요)을 브라우저에서 직접 호출해 위치가 Snaptok 서버를 거치지 않게 한다. SDK를 쓸 수 없으면 `places_seed.json`의 매장 목록을 쓴다. 매장 목록은 위치가 1.5km 이상 바뀔 때만 다시 찾는다.

### 5.5 시간 알림 (P0: 앱 안, P1: 구글 캘린더)
- 앱이 열려 있으면 1분마다, 그리고 앱을 열 때 일정을 검사해 알림 시점(4.5의 알람 기준)에 도달했고 아직 알리지 않은 일정이 있으면 상단 배너로 알린다. 예: "내일 18:00 마감 · AI 서비스 아이디어톤 신청". 탭이 백그라운드이고 브라우저 알림 권한이 있으면 시스템 알림도 보낸다. 알린 기록은 localStorage에 남겨 중복 알림을 막는다.
- 앱이 닫혀 있을 때의 시간 알림은 구글 캘린더 동기화(P1)가 담당한다고 설정 화면에 안내한다.

## 6. 휴대폰 실기기 테스트

브라우저의 위치 기능과 알림 기능은 HTTPS(또는 localhost)에서만 동작한다. 휴대폰에서 노트북 서버를 `http://192.168...`로 열면 위치가 막힌다. README에 `cloudflared tunnel --url http://localhost:8000`처럼 HTTPS 임시 주소를 만드는 방법을 적고, 그 주소를 카카오 JS SDK 허용 도메인에 등록해야 한다는 점도 적어라(임시 주소가 바뀌면 SDK 대신 시드 매장 목록으로 동작).

## 8. 완료 기준 (시뮬레이터 모드, 데모 모드, 시연 날짜 2026-09-20)

1. 연남동 맛집 이미지를 올리면 [저장하기] 없이 보관함 맛집에 저장되고, 상단 배너에 "근처에 가면 알려드릴게요"가 뜨며, "지금 이 주변" 등록 수가 늘어난다.
2. 설정 시뮬레이터에서 "연남동"을 누르면 10초 뒤 지오펜스 배너 "근처에 저장해 둔 연남동 파스타집이 있어요 · 맛집"이 뜨고, 누르면 원본 이미지가 있는 상세가 열린다. 10초 안에 "멀리"를 누르면 알림이 없다.
3. 스타벅스 기프티콘 이미지를 올리면 만료 일정과 보관함 쿠폰이 함께 생긴다. "역삼 스타벅스 앞"으로 이동하면 "근처에 스타벅스…가 있어요 · 9/25까지인 쿠폰이 남아 있어요"가 뜨고, [사용했어요] 후에는 뜨지 않는다.
4. 공모전 포스터는 일정 2건, 해커톤 포스터는 행사 일정 1건(마감 없음)으로 저장된다. 세미나 안내는 확인 필요에 들어가고, [일정으로]를 누르면 LLM 재호출 없이 저장된다.
5. 같은 이미지를 다시 올리면 "중복 건너뜀"으로 표시되고 새 항목이 생기지 않는다. [되돌리기]를 누르면 일정·보관·지오펜스가 함께 취소된다.
6. 알림 시점이 된 일정이 있으면 앱을 열었을 때 시간 알림 배너가 뜨고, 같은 알림이 반복되지 않는다.
7. 새로고침해도 모든 데이터가 유지되고, 이미지 30장을 올려도 저장 오류가 없다.
8. 분석 결과 시트를 그냥 닫아도 저장 결과가 유지된다.
9. 네트워크 요청 중 Snaptok 서버로 가는 요청에 사용자 위치가 없다.
10. (P1) `CALENDAR_SYNC=google`이면 구글 캘린더에 일정과 알람이 생기고 되돌리기 시 삭제된다. 휴대폰에서 HTTPS 주소로 실제 위치 모드가 동작한다.
11. 화면 구성과 디자인이 데모와 같다.

## 9. 하지 말 것

- 데모의 화면·디자인을 새 프레임워크로 다시 만들지 마라.

- 사용자 위치를 Snaptok 서버로 보내거나 저장하지 마라.
- API 키를 웹 코드나 커밋에 넣지 마라(카카오 JS 앱 키는 도메인 제한을 건 경우에만 웹에 둔다).
- 테스트를 통과시키려고 LLM 출력이나 기대 결과를 특정 이미지에 맞춰 하드코딩하지 마라.
